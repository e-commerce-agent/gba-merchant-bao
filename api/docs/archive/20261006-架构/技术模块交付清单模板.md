# 技术模块交付清单模板

每个技术模块必须在同一个 OpenSpec change 中提交下列证据，并在缺项时保持未完成状态：

| 证据项 | 必须回答的问题 | 交付物/验证 |
| --- | --- | --- |
| 依赖与配置 | 本模块实际使用了哪些 Maven 依赖、配置和外部服务？ | POM、profile 配置、启动检查 |
| 数据库 | 新表字段、`merchant_id`、唯一键、索引、数据映射和回退如何处理？ | Flyway 版本、schema contract、备份/恢复记录 |
| 接口 | 新旧路由、请求/响应、错误码、鉴权和特殊协议是什么？ | Controller、Springdoc YAML、兼容回归 |
| 日志 | 模块、requestId、租户、耗时、稳定错误码和敏感字段如何记录？ | Logback/MDC 检查、脱敏测试 |
| 测试 | 单元、集成、契约、外部依赖不可用和跨租户场景是否覆盖？ | JUnit 报告、Testcontainers 或降级证据 |
| 运维与回退 | 失败如何停止、重试、降级或恢复？ | 演练命令、失败记录、回退说明 |

## 使用规则

1. 依赖只有在模块真实使用时加入；空依赖、空配置和未使用中间件不能作为完成证据。
2. 商户私有表的读写必须从服务端认证上下文取得 `merchant_id`，更新和删除 SQL 也必须带租户条件。
3. 已执行 Flyway 文件不可修改；结构或数据修复追加新版本并记录 checksum。
4. 登录模块另开 change 时才加入 Redis 登录会话、认证表、认证日志和 Redis 集成测试。
5. 四个 Agent 亮点各自另开 change；每个亮点完成时独立量化、评测、留证和归档。本基础 change 不创建新的 Agent 评测模板、指标或结果。
