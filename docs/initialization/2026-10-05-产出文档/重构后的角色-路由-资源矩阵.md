# 重构后的角色、路由与资源矩阵

## 1. 文档用途

本文件配合 `docs/initialization/设计手稿.md` 的“现在的业务场景和技术模块”使用，固定首期 3C 配件电商客服的角色、入口、资源边界，以及商户宝 Agent 四个既有技术亮点的冻结范围。

## 2. 角色矩阵

| 主体 | 登录状态 | 租户范围 | 可访问能力 | 明确禁止 |
|---|---|---|---|---|
| 未登录访问者 | Spring Security 匿名状态，不创建 guest 账号 | 通过店铺编码解析公开商户 | 公开商品、SKU 规格、公开库存状态、公开知识问答 | 订单、物流、历史会话、反馈、文档管理、私有 Tool |
| 消费者 | 手机号+短信验证码 | 当前消费者所属商户 | 继承公开商品、SKU、公开库存和公开知识问答；Agent 会话；只读本人订单、本人物流、历史会话和反馈 | 下单、支付、订单创建、其他消费者资源、商户后台、其他商户数据、写操作 Tool |
| 商户管理员/客服 | 商户编码+用户名/手机号+密码 | 当前登录商户 | 本商户商品、SKU、库存、知识库、文档任务、会话接管、人工回复、订单和物流工作台 | 其他商户数据、平台级配置、未经授权的消费者隐私 |
| 平台管理员 | 后续实现 | 平台级 | 后续管理商户账号、模型配置、系统运行状态和任务状态 | 本期不作为核心流程依赖，不使用虚假的 `merchant_id=0` |

授权判断分三层：先判断资源属于哪个商户，再判断主体能做哪类操作，最后判断消费者是否拥有具体订单、物流、会话或反馈资源。`merchantId`、`customerId` 等身份由服务端上下文提供，不能由请求参数或 Agent 模型覆盖。

## 3. 路由矩阵

| Web 路由 | 使用主体 | 主要内容 | 认证要求 |
|---|---|---|---|
| `/public/**` | 未登录访问者、消费者 | 公开商城、商品/SKU、公开库存、公开知识问答 | 公开访问；通过店铺编码确定商户 |
| `/consumer/**` | 消费者 | 登录、Agent 对话、订单、物流、历史会话、反馈 | 消费者登录 |
| `/merchant/**` | 商户管理员/客服 | 商品/SKU、库存、知识库、文档任务、会话工作台、订单物流 | 商户员工登录 |
| `/platform/**` | 平台管理员 | 商户、模型和系统运行管理 | 后续平台管理员登录 |

所有入口属于同一个 Web 应用，不拆多仓库，不做微前端。后端接口统一使用 `/api/v1/**`，不在 URL 中添加调用方名称。

## 4. 资源访问矩阵

| 资源 | 匿名访问者 | 消费者 | 商户管理员/客服 | 平台管理员 |
|---|---|---|---|---|
| 公开商品、SKU | 读公开字段 | 读公开字段 | 读写本商户 | 后续按平台权限 |
| 库存 | 读公开可售状态 | 读公开可售状态 | 读写本商户库存 | 后续按平台权限 |
| 订单 | 无 | 只读本人；数据来自种子或商户后台已创建订单 | 按商户和权限查看/维护 | 本期不访问商户私有业务数据 |
| 物流 | 无 | 只读本人订单物流；数据来自种子或商户后台已有物流 | 按商户和权限查看/维护 | 本期不访问商户私有业务数据 |
| Agent 会话 | 无历史会话 | 本人会话和 SSE 问答 | 本商户会话、接管和人工回复 | 本期不参与 |
| 知识库/文档任务 | 无 | 公开知识问答结果 | 本商户维护和查询 | 后续查看运行状态 |
| 问答反馈 | 无 | 提交和查看本人反馈 | 处理本商户反馈 | 后续按平台权限 |

## 5. Agent 四个技术亮点冻结清单

以下四项是商户宝 Agent 电商客服已有技术亮点。本次“重构后的业务场景+技术模块”只保留其业务场景和技术定位，不重新设计、不改写、不提前实现，也不将它们扩展为新的 Agent 能力。

1. **RAG**
   - 基于LangChain4j构建商品资料、售后政策和店铺规则知识库，完成语义切分、向量化、Query改写、混合检索、Rerank与来源引用；通过自建评测集和Badcase回流优化检索及回答质量。

2. **Function Calling**
   - 基于LangChain4j Function Calling封装商品、库存、订单和物流查询工具，通过服务端身份注入、商户/用户数据隔离、参数校验、敏感字段脱敏、有限重试与降级兜底，防止越权和失控调用。

3. **RabbitMQ**
   - 针对商户批量文档解析与向量化耗时问题，使用RabbitMQ将导入改造为异步任务，结合发布确认、手动ACK、幂等消费、重试、死信和进度查询，支持失败任务定位与人工重投。

4. **Redis ChatMemory**
   - 使用Redis ChatMemory保存活跃会话窗口，并将完整对话持久化到MySQL；通过token预算截断、历史摘要、会话隔离和缓存过期恢复控制上下文规模，支撑可审计的多轮对话。

技术亮点的真实数据后续根据评测和测试填写；没有测试结果时不填写虚构百分比。

本 change 不新增退款、改价、发货等写操作 Tool，不增加 MCP、多 Agent 编排或复杂平台。
