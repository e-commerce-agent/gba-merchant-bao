# 旧接口迁移清单

更新时间：2026-10-06

本清单是 `refactor-foundation-stack-and-migrations` 的兼容证据入口。旧接口在调用方确认、新接口契约导出和回归完成前继续保留。

## 路由盘点

| 路由范围 | 当前来源 | 迁移策略 | 退役条件 |
|---|---|---|---|
| `/admin/**` | `merchant-server/controller/admin` | 保留旧响应和字段语义；新模块按 `/api/v1` 增量适配 | 调用方、Apifox、旧前端和相关测试全部迁移并完成回退验证 |
| `/user/**` | `merchant-server/controller/user` | 保留旧响应和字段语义；新模块按 `/api/v1` 增量适配 | 调用方、Apifox、旧前端和相关测试全部迁移并完成回退验证 |
| `/api/v1/**` | 本 change 起新增 | 使用 Springdoc 代码先行、`code/message/data/requestId` 和公共错误码 | 不适用 |

## 响应兼容

- 旧接口继续使用当前 `code/msg/data` 语义；不得因为新接口引入而静默改成 `message` 或 `code=0`。
- 新 `/api/v1` 普通 JSON 使用 `code=0` 表示成功，包含 `message`、`data` 和 `requestId`；`X-Request-Id` 与 JSON 中的 `requestId` 一致。
- 文件上传、异步任务和 SSE 使用各自的 MIME、202/task 或事件协议。
- 旧接口的迁移、弃用和删除必须在本清单补充证据，并由独立 change 处理破坏性变更。

## 证据要求

每个迁移接口至少记录：旧路径和新路径、请求方、字段映射、HTTP/业务码变化、OpenAPI 快照、自动化测试、Apifox 场景和回退方式。

### Token、会话与错误兼容

- 旧管理端 token、旧消费者 authentication、新 Authorization: Bearer 分属不同协议；新旧 token 交叉拒绝，旧 /admin、/user 保留路径、请求/头及 code/msg/data（成功 code=1），不静默改 code=0/message，也不宣称获得新三层授权。
- 新 JSON 用 code/message/data/requestId，成功 code=0，错误 data=null；X-Request-Id 匹配 body，认证响应 no-store。刷新/退出凭证放 POST body，不放 URL，不记录 token/body。
- 新 HS256 key 为不同角色独立 Base64 随机值；legacy JwtUtil 已切换为 Base64 解码和显式 HS256，既有旧 token 不保证有效，调用方须重新登录。新令牌 issuer/audience/claims/Redis 与旧协议隔离，不做默认租户桥接。
- 新 access 标称两小时、exp capped original absolute；消费者 idle7天/absolute30天，员工 idle1天/absolute7天。idle 只使 active 失效，有效 refresh 可恢复；absolute 不滑动，超过才须重新短信/密码验证。control/refresh 全丢失或已撤销不能恢复，故障 503。
- 短时刷新重试只接受同旧摘要、同 refreshRequestId、10秒内且仍当前代；同次响应认证加密短存。真实重放仅撤销当前 sid/family；退出原子禁用其 active/refresh，墓碑及已知摘要支撑重复退出，不能随后自动刷新复活。
- 未认证 401，角色或显式保护店铺 URL 与 token 租户不符 403，具体跨租户/非本人/不存在统一 404；员工唯一冲突 409，消费者自动建号不返回重复注册冲突。统一登录失败避免枚举，旧业务码不静默重写。
- 当前 dev/test 与短期生产 access+refresh 使用 localStorage，按店铺+类型分区，切店保留其他凭证，同店 tabs 协调刷新/退出并丢弃迟到结果。A 登录不等于 B 登录，B 可匿名浏览，私有功能使用 B 凭证；通用私有接口误收 A token 仅按 A Actor，不推断浏览器 B 页面。XSS 风险明确，Cookie 分离存储另开 change。
