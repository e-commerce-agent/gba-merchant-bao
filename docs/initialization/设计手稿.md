## 需求

### 1. 项目定位

面向广州中小型消费品电商和跨境零售的中小商户，为消费者与人工客服提供商品/售后知识问答，以及订单、库存、物流查询的电商客服 Agent

### 2. 产品

3C 配件

电商 Agent 客服能回答的：

- 商品兼容性：是否支持某手机型号、接口类型、快充协议。
- SKU 差异：颜色、长度、功率、插头规格和套装内容。
- 库存问题：某个具体 SKU 是否可售。
- 售后问题：质保时间、退换条件、人为损坏是否保修。
- 物流问题：是否发货、承运商、最新轨迹和预计送达。

### 3. 角色

一个 3C 配件电商商户作为样板租户，但架构仍按多商户设计

支持未登录公开浏览

未登录访问者是 Spring Security 匿名状态，不是数据库角色，不创建 guest 账号

| 角色 | 在系统中做什么 |
|---|---|
| 未登录访问者（非持久化角色） | 浏览公开商品/SKU、公开库存状态和公开知识问答；不能查订单、物流、历史会话或私有 Tool |
| 消费者 | 与 Agent 对话，咨询商品和售后，查询本人订单与物流 |
| 人工客服 | 使用同一客服工作台查看 Agent 对话、接管低置信度或异常会话 |
| 商户运营 | 维护商品/SKU/库存，上传知识文档，查看导入任务与问答反馈 |
| 系统管理员 | 管理商户账号、模型配置和系统运行状态，不查看商户私有业务数据 |

1. 首期角色最小化
   平台管理员、商户管理员 + 客服、消费者，不提前做 RBAC
   先把商户运营和人工客服合成 1 个角色
2. 登录方式
   消费者首期：手机号+短信验证码；邮箱可选绑定。
   商户员工首期：商户编码+用户名/手机号+BCrypt 密码。
   授权同时检查商户、角色和用户资源归属。

4. 业务入口
Web 端，没有加入微信小程序

1 个前端应用、1 个登录体系、1 个权限模型

1. 公开商城
未登录访问者、消费者

商品、SKU、公开库存、公开知识问答

2. 消费者中心
消费者

手机号登录、Agent 对话、订单、物流、历史会话、反馈

3. 商户客服工作台
商户管理员 + 客服（首期同个角色）

查看会话、接管对话、商品 + SKU、库存、知识库、任务、问答反馈

4. 平台管理后台

系统管理员

   关键字段

   关键约束

   - (merchant_id, external_id) 唯一
   - (merchant_id, phone) 唯一（首期为商户内消费者账号）

   phone 保存规范化原始手机号，仅用于服务端登录匹配和唯一约束；展示、响应和日志运行时调用 maskPhone(phone)
   phone_masked 不能作为登录字段或唯一索引字段；历史库若已有该列，迁移时仅兼容保留并停止由新代码写入，核对后再退役

4. 表 platform_user

   关键字段

   - id、username、password_hash、display_name、role、status、password_changed_at

   关键约束

   - username 全局唯一

   平台管理后台 不使用虚假的 merchant_id=0

首期角色最小化

- 平台管理员（首期不实现）、商户管理员+客服（首期先合并为 MERCHANT_STAFF）、消费者，不提前做 RBAC

Tool 查询消费者订单同时校验 merchant_id + customer_id

5. Redis 登录会话（不建 MySQL session 表）

登录成功生成 sid，JWT 携带 sid，Redis 保存当前有效登录会话

   1. Key auth:session:{sid}
      Value：subjectType、subjectId、merchantId、permissions、issuedAt
      TTL 不长于 JWT 有效期
      每个受保护请求校验

   2. Key auth:subject-sessions:{subjectType}:{subjectId}
      Value：当前主体的 sid 集合
      支持账号禁用、员工离职、改密时全端下线

   3. Key auth:sms:code:{merchantId}:{phone}
      Value：验证码摘要、验证失败次数
      TTL 短 TTL
      成功验证后原子删除

   4. Key auth:sms:send-limit:{merchantId}:{phone}
      Value 发送次数 + 冷却信息
      TTL 防重复发送
      还需 IP 维度限制

手机号 HMAC+不可逆摘要，不把验证码写入应用日志里
不能在 sid miss 时 MySQL 自动恢复
logout 只撤销当前 sid
   账号禁用、员工离职、密码修改、角色+权限变更 或者是 安全事件撤销该主体全部 sid，避免 Redis 权限快照
   首期不创建 login_session 表，有设备管理、合规审计 或者是 长期登录历史需求再设计持久化登录审计表（跟操作审计表不一样）

      至少 1 条有多段轨迹，1 条尚未发货
   6. 知识
      兼容性、快充协议、质保、退换货、店铺规则文档
   7. 会话
      local + test 加载最小会话和消息种子
      用于 ChatMemory 恢复、越权和多轮评测
      prod 不加载
      种子不作为生产迁移内容

所有种子使用固定业务编码和幂等写法，Apifox、集成测试和评测集引用业务编码，不依赖每次变化的自增值

#### 1.3 租户 角色 资源归属 3 层授权

1. 租户隔离
   解决“属于哪个商户”
   所以商户私有查询 或者是 更新都带 merchant_id

2. 角色权限
   解决“能做哪类操作”
   消费者、商户客服+商户运营、平台管理员使用最小权限
   首期可用枚举角色和接口权限矩阵
   先不建复杂 RBAC

3. 用户资源归属
   解决“能访问谁的数据”
   消费者只能访问自己的订单、物流、会话和反馈
   SQL 直接使用 merchant_id + customer_id + resource_id 查询 或者是更新

4. 典型索引
   - orders：(merchant_id, customer_id, placed_at, id)
   - chat_session：(merchant_id, customer_id, last_message_at, id)
   - chat_message：(merchant_id, session_id, sequence_no) 唯一
   - shipment：先通过受用户归属约束的 orders 关联，禁止只凭 tracking_no 对消费者公开

索引遵循等值列在前、范围+排序列在后
以实际 EXPLAIN 和慢查询证据调整

5. 越权测试数据（这里是测试，比 1.2 3C 样板租户 造数据更详细）
   至少准备 2 个租户，每个租户至少 2 个消费者
   覆盖同租房跨用户、跨租户同用户、普通消费者访问后台、商户客服访问其他商户四类失败用例
   不只验证读取
   更新、删除、SSE 会话、Tool 调用同样测试

### 2. API 与数据库的关系

API 按业务用例设计，数据库按持久化和一致性设计，它们 2 个不一表一个 CRUD 机械映射

设计文档分层架构图：

```text
HTTP/SSE -> Controller -> Request/Response -> Application/Domain Service
         -> Mapper/Repository -> MySQL
         -> Redis/RabbitMQ/Milvus/LLM adapter
```

规则：

1. Controller 不返回 Entity，Request/Response 与表字段分别演进
2. merchantId、userId 从认证上下文注入，不接受前端或模型随意传入
3. 每条业务查询在 Service 和 SQL 两层带租户条件，仅在 Controller 校验不够
4. 一个 API 组合多表和中间件
   订单详情组合 orders + order_item + shipment + shipment_track
   一个表可以服务多个用例
5. 数据库事务只保证本地一致性，RabbitMQ、Milvus 等跨资源流程使用任务状态、幂等键和补偿，不伪装 1 个大事务
6. API 不暴露数据库实现细节：自增主键、软删除字段、内部异常堆栈

#### 3.2 普通 JSON 响应格式

```json

  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "..."
}
```

#### 3.3 响应约定

1. HTTP 状态表达协议结果
   200/201/202、400、401、403、404、409、413、422、500
2. body.code 表达稳定业务结果
   message 显示 + 排查
3. X-Request-Id 响应头与 JSON 中的 requestId 一致
4. 文件上传、已建立连接的 SSE、文件上传不是普通 JSON 响应格式
5. 文件上传声明 MIME、大小限制和 413
6. 异步文档导入返回 202，包含 taskId、status、statusUrl
7. 201 返回 Location
